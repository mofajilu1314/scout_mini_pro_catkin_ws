# 3D_README_3：实施路线图与验收标准

按 [3D_README.md](3D_README.md) 的方向与 [3D_README_2.md](3D_README_2.md) 的架构，把第二阶段拆成可执行里程碑。完成 M3 即可宣称「在 3D 越野仿真里跑出来」；M4～M5 为加固与真机预备。

---

## 一、里程碑总览

| 里程碑 | 名称 | 核心交付 | 预估难度 |
|--------|------|----------|----------|
| **M0** | 文档与方向冻结 | 本系列 `3D_README*`（已完成） | — |
| **M1** | 越野仿真舞台 | 非平坦 Gazebo world + Scout 可遥操作 | ★★ |
| **M2** | 深度几何感知 | 点云 → 距离特征 / 局部可通行性格网 | ★★★ |
| **M3** | TD3 局部导航跑通 | 训练 + 推理：随机目标、避障、发 `cmd_vel` | ★★★★ |
| **M4** | 2.5D 全局规划接入 | 全局路径/引导点 + TD3 跟踪局部目标 | ★★★★ |
| **M5** | LIO-SAM 并行 | 3D 位姿替代纯平面 AMCL 假设 | ★★★★★ |

图像识别 / ORFD：**M6+（第三阶段）**，不写入第二阶段必做。

## 二、分里程碑说明

### M1 — 越野仿真舞台

**做什么**

- 新建 `worlds/offroad_*.world`：至少含缓坡、浅坑、散落障碍；地面摩擦合理。  
- Launch：加载该 world + 生成 Scout（方块车或官方车二选一，建议先方块车）。  
- 键盘 teleop 验证：能爬缓坡、会打滑/侧倾时可感知。

**验收**

- [ ] `roslaunch … offroad_teleop.launch`（名称自定）可稳定启动。  
- [ ] 深度话题、`cmd_vel`、TF 与第一阶段同类自检命令通过。  
- [ ] 不再依赖「只有平地 room」才能演示第二阶段。

**参考**：`gazebo_autonomous_driving` 的 dirt/grass 赛道仅作场景灵感，不强制迁 ROS2。

---

### M2 — 深度几何感知

**做什么**

- 节点订阅深度 `PointCloud2`：  
  - 滤除地面 / 车体；  
  - 输出扇区最近距离向量（供 TD3）；  
  - （可选）投影为局部 `OccupancyGrid` 或简单 elevation。  
- RViz 显示点云与可通行性。

**验收**

- [ ] 障碍靠近时扇区距离明显变小。  
- [ ] 缓坡不被误判为「墙」（阈值需调：高度带、俯仰补偿）。  
- [ ] 频率满足控制（建议 ≥10 Hz 特征输出）。

**注意**：这是「眼睛」的几何版；**不是** CNN。

---

### M3 — TD3 局部导航（第二阶段主验收）

**做什么**

- 移植/改写 DRL-AUV 或 [DRL-robot-navigation](https://github.com/reiniscimurs/DRL-robot-navigation) 的 TD3 训练脚本。  
- `GazeboEnv` 对接 Scout：`reset` 位姿、订阅特征与里程计、发布 `cmd_vel`。  
- 奖励与 `done` 条件按 [3D_README_2.md](3D_README_2.md) 初版实现。  
- 提供 `train_td3.py` / `test_td3.py` + 说明（Conda 环境、双终端、杀进程命令）。

**验收**

- [ ] 空旷/简单障碍场景：随机目标到达率达到约定阈值（例如验证集 ≥70%，数字可按场景再定）。  
- [ ] 碰撞率可接受；训练曲线（TensorBoard）可见进步。  
- [ ] **推理模式**不依赖人工键盘即可走向目标。  
- [ ] 与第一阶段 launch **互不覆盖默认参数**。

**完成 M3 = 第二阶段主线「跑出来」的最低标准。**

---

### M4 — 2.5D 全局规划接入

**做什么**

- 在可通行性格网上跑 A\*（或 RRT\*）。  
- 沿全局路径取前瞻点作为 TD3 的 `local_goal`。  
- 对比实验：仅 TD3 随机目标 vs 全局引导 + TD3。

**验收**

- [ ] RViz 可见全局路径与局部目标。  
- [ ] 中等复杂越野场景下，引导版比纯随机 TD3 更稳、更少绕死。  

---

### M5 — LIO-SAM 并行基建

**做什么**

- 确认仿真或真机具备 **多线点云 + 9 轴 IMU** 话题。  
- 接入 LIO-SAM，输出 `map→odom`（或项目约定的位姿）。  
- 用该位姿替换 RL/规划中的粗糙定位。

**验收**

- [ ] 越野轨迹回放漂移明显小于纯轮式里程计。  
- [ ] 文档写清外参、`params.yaml`、与 Scout 话题 remap。

**说明**：若仿真短期只有 2D LaserScan，M5 可先在真机 bag / 换雷达插件后做，不阻塞 M3。

---

## 三、建议开发顺序（周粒度示意）

```text
Week 1     M1 越野世界 + teleop
Week 2     M2 深度特征节点
Week 3–5   M3 TD3 训练调通（主耗时）
Week 6     M4 2.5D 全局规划拼接
并行空档   M5 LIO-SAM 调研与传感器对齐
之后       第三阶段：ORFD / 多模态 freespace
```

实际进度随算力与仿真稳定度浮动；**不要**在 M3 未通前并行大干 ORFD。

## 四、风险与备选

| 风险 | 表现 | 备选 |
|------|------|------|
| 深度点云噪声/地面误检 | RL 学不会 | 先用 2D/3D 激光扇区特征训通，再换深度 |
| 仿真过慢，TD3 不收敛 | 训练极慢 | 降图形、简化 world、缩短 episode；或先 2D 障碍场预训练再迁移越野 |
| 侧倾翻车 | 频繁 done | 限速、限 ω；奖励加姿态惩罚；坡度场景渐进课程学习 |
| LIO-SAM 仿真雷达不够 | 无法建 3D 图 | M5 延后；定位暂用 Gazebo 真值位姿（仅仿真）加速 RL |
| 范围蔓延 | 同时搞 CNN+RL+LIO | 严格按 M1→M3 门禁，ORFD 进第三阶段 |

## 五、与申报目标的对应（写材料可用）

项目名方向：**基于 ROS 的越野环境生态友好型自动驾驶**。

| 申报要素 | 第一阶段 | 第二阶段 | 第三阶段（规划） |
|----------|----------|----------|------------------|
| ROS 自主导航 | ✅ 室内 2D | ✅ 越野仿真 RL + 2.5D | 加固真机 |
| 合理路径规划 | ✅ A\* 平面 | ✅ 可通行性代价规划 | 语义代价 |
| 语义 / 目标识别 | ❌ | 接口预留 | ✅ ORFD 等 |
| 生态友好 | 概念 | 可通行性避免硬冲地形 | 植被等语义避让 |

## 六、立即可以做的第一件实事

文档已齐后，建议下一动作只做一件：

1. 在包内（或新包）添加 **`offroad_simple.world` + launch**，让 Scout 出现在带缓坡的地面上；  
2. 确认 `/…/depth/points` 有数据；  
3. 再开 M2 特征节点。

不要一上来就克隆四个 GitHub 仓库并行编译。
