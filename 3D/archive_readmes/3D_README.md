## 一、第一阶段卡在哪里（为什么必须进第二阶段）

当前闭环可以概括为：

```text
2D LaserScan → slam_toolbox / OccupancyGrid → AMCL → 2D A* → Pure Pursuit → cmd_vel
```

这在**平坦室内房间**足够，但越野自动驾驶会撞上三道硬墙：

1. **环境是 3D 的**：坡度、坑洼、台阶、可通行性 ≠「栅格上有没有墙」。现有 `room.pgm` 式 2D 地图表达不了地形。  
2. **决策不能只靠手写规则**：复杂越野下「往哪走」更适合用学习型局部策略（RL）补足，而不是无限堆 if-else。  
3. **「眼睛」最终要多模态**：RGB + 深度 / 点云 +（后期）语义自由空间；但**第二阶段先不把 CNN 语义分割当主路径**，避免同时开太多战线。

因此第二阶段的目标不是「立刻端到端多模态大模型」，而是先搭好**能在 3D 越野仿真里跑起来**的桥。

## 二、第二阶段明确方向（已拍板）

### 主线（按你的 idea 定稿）

> **先放图像识别 / 语义分割；优先：深度相机几何感知 + 深度强化学习局部导航 + 2.5D/3D 可通行性路径规划，让小车在越野仿真里自主跑起来。**

| 层级 | 第二阶段做法 | 刻意后置 |
|------|--------------|----------|
| 感知 | 深度点云 → 高程 / 简单几何可通行性（坡度、台阶高度） | ORFD 等多模态自由空间网络、复杂语义分割 |
| 定位建图 | 仿真内可先用里程计+简化地图；室外主推 **LIO-SAM**（LOAM 的演进） | 继续死磕室内 AMCL + 2D 地图当唯一方案 |
| 全局规划 | 在 **traversability / elevation grid（2.5D）** 上做 A\* / RRT\* | 继续用纯 2D OccupancyGrid A\* 当最终方案 |
| 局部决策 | **TD3 等 DRL** 输出 `cmd_vel`（避障 + 朝向目标） | 纯 Pure Pursuit 规则跟线当唯一控制 |
| 平台 | 继续 **ROS Noetic + Gazebo + Scout Mini** | 立刻整仓迁 ROS 2 Jazzy（可作远期参考） |

### 一句话技术路线

```text
深度相机点云 ──► 局部高程/可通行性层 ──► (可选) 全局 2.5D 规划出引导点
         │                                    │
         └──────────► TD3 局部策略 ◄───────────┘
                           │
                      /cmd_vel → Scout
```

并行能力建设（不挡主线）：接入 **LIO-SAM**，为真车 / 大场景提供 3D 位姿与点云地图。

## 四、成功标准（第二阶段「跑出来」的定义）

做到以下即算第二阶段主线达标（细节见 [3D_README_3.md](3D_README_3.md)）：

1. 有一块**非平坦越野 Gazebo 世界**（坡/坑/散石等，不再只是 room 平地）。  
2. 深度相机点云能稳定转成**局部可通行性表示**（哪怕先用几何阈值，不用神经网络）。  
3. 有一条 **TD3（或同类 DRL）训练/推理闭环**：状态含深度（或由其投影的距离特征）+ 目标相对位姿 → `cmd_vel`。  
4. 全局侧至少有一个 **2.5D 规划器**给出目标或引导点（可先简化，再逐步换 RRT\*）。  
5. 文档与 launch 可复现；与 `README_3` 一键室内导航**互不破坏**。
